# MiniChroma

A native SwiftUI macOS menu-bar RGB controller for the **wired Razer DeathAdder V2 Mini (`1532:008C`)**.

MiniChroma combines the mouse's firmware effects with continuously streamed colours based on Mac volume, battery, CPU temperature, and audio. Firmware effects run on the mouse after one command. Live effects are generated by the Mac while the app runs.

## Compatibility

| Component | Tested support |
| --- | --- |
| Mouse | Wired Razer DeathAdder V2 Mini, USB VID `0x1532`, PID `0x008C`, firmware 1.2 |
| Mac | Apple Silicon, macOS 15+; hardware testing on an Apple M4 MacBook Air running macOS 15.8.2 |
| CPU temperature | Experimental read-only AppleSMC backend for validated M4 CPU sensors |
| Other mice | Require model-specific implementation and hardware verification; currently unsupported |

The app deliberately matches this one mouse. A similar product name, another DeathAdder model, a wireless receiver, or another USB PID does not imply compatible commands. See [adding a device](CONTRIBUTING.md#adding-another-mouse) or open a **Device support request** using the repository's Issues tab. A request invites investigation and does not guarantee support.

## Features

- On-mouse: off, static, spectrum, reactive, and single/two-colour/random breathing.
- Live Mac effects: volume, battery, system audio, custom rainbow and pulse, plus experimental M4 CPU temperature.
- Adjustable update rate (1–30 Hz), smoothing, brightness, thresholds, and named presets.
- Launch at login, optional restore on launch, sleep/wake handling and reconnect attempts.
- Serialized USB request/reply exchanges, response validation, bounded recovery, and a process lock against competing MiniChroma instances.
- Hardware diagnostics and command-line tools.

The default live rate is 10 Hz. A five-minute test on the listed mouse delivered **7,500 validated frames at a 25 Hz target with zero errors**. This is evidence for that device and setup, not a guarantee for every hub or firmware. See [verification](VERIFICATION.md).

## Build and run

Requires Xcode with the macOS SDK. There are no third-party runtime dependencies.

```sh
./build.sh
open dist/MiniChroma.app
```

The script builds the `MiniChromaApp` Xcode scheme in a temporary directory, signs for local use, verifies the signature, and creates `dist/MiniChroma.app` and `dist/MiniChroma.zip`. Set `MINICHROMA_OUTPUT_DIR` to an absolute directory to choose another output location. Builds are ad hoc signed, not Developer ID notarized.

Alternatively, open `MiniChroma.xcodeproj`, select **MiniChromaApp**, and Run. This scheme builds the `.app`; the separate Swift package executable scheme serves command-line development.

Move the built app to Applications before enabling launch at login. Open it, then click the mouse icon in the menu bar. The app has no Dock icon.

## Using the controller

Choose an effect, adjust its controls, and click **Apply**. **Light off** selects firmware off. **Stop** ends live updates but leaves the last colour displayed.

Volume maps green → yellow → red and uses black when muted. Battery maps green at full charge toward red at empty. Adjust the yellow threshold in Settings. Some audio outputs do not expose software volume; battery requires an internal Mac battery.

Audio reactive uses ScreenCaptureKit to measure system output locally. macOS may request Screen & System Audio Recording permission for the app. No microphone is used and no recording is saved or transmitted. Adjust primary colour, gain, noise gate, and smoothing for the audio source.

CPU temperature displays the hottest validated M4 CPU-core sensor and its key. The read-only AppleSMC interface is private and experimental; an OS update may change it. It samples once a second, never controls fans or writes SMC settings, and reports unavailable if its sensor requirements are not met. Cool/hot thresholds are adjustable in Settings.

Presets are saved in `~/Library/Application Support/MiniChroma/presets.json`. Settings also controls launch at login and restore on app launch. Automatic restore defaults off.

## Diagnostics and tests

Quit MiniChroma and any other RGB controller before running command-line hardware diagnostics:

```sh
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer swift test
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer swift run minichroma-diagnostic read
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer swift run minichroma-diagnostic temperature
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer swift run minichroma-diagnostic stream 25 300
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer swift run minichroma-diagnostic off
```

`read` checks firmware without changing the logo. `stream` animates the logo for the requested duration, validates every reply, and finishes with off. `off` additionally sets brightness to zero and reads it back. Hardware tests require the listed mouse to be connected.

The app's Diagnostics window offers metadata reads and shorter effect/rate tests. The app executable also accepts `--system-test` (real volume/battery/CPU/rainbow/pulse pipeline) and `--audio-test` (real audio capture with a short local Apple sound). These change lighting temporarily and finish with off/zero brightness.

Visual effect behavior, pointer usability, physical reconnect, sleep/wake, and login launch need observation on the actual setup. Automated tests and USB acknowledgements cannot prove those physical interactions.
