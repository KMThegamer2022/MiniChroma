# MiniChroma

A native SwiftUI macOS menu-bar RGB controller for the **wired Razer DeathAdder V2 Mini (`1532:008C`)** and **Razer Ornata V3 X keyboard (`1532:02A2`)**.

MiniChroma combines the mouse's firmware effects with continuously streamed colours based on Mac volume, battery, CPU temperature, and audio. Firmware effects run on the mouse after one command. Live effects are generated by the Mac while the app runs.

## Compatibility

| Component | Tested support |
| --- | --- |
| Mouse | Wired Razer DeathAdder V2 Mini, USB VID `0x1532`, PID `0x008C`, firmware 1.2 |
| Keyboard | Razer Ornata V3 X, USB VID `0x1532`, PID `0x02A2`, transaction ID `0x1F`. Verified on hardware: firmware query, static colour, brightness, off, and raw colour frames at the mouse's rate. Spectrum is unverified; breathing, reactive and audio effects are not supported on the keyboard yet |
| Mac | Apple Silicon, macOS 15+; hardware testing on an Apple M4 MacBook Air running macOS 15.8.2 |
| CPU temperature | Experimental read-only AppleSMC backend for validated M4 CPU sensors |
| Other mice | Require model-specific implementation and hardware verification; currently unsupported |

Sync keyboard with mouse mirrors the mouse's lighting to the keyboard. Turn it off to give the keyboard its own effect, with audio effects kept on the mouse. The app deliberately matches these two devices. A similar product name, another DeathAdder model, a wireless receiver, or another USB PID does not imply compatible commands. See [adding a device](CONTRIBUTING.md#adding-another-mouse) or open a **Device support request** using the repository's Issues tab. A request invites investigation and does not guarantee support.

## Features

- On-mouse: off, static, spectrum, reactive, and single/two-colour/random breathing.
- Live Mac effects: volume, battery, system audio, custom rainbow and pulse, plus experimental M4 CPU temperature.
- **Beat Adapt:** PCM percussion/onset analysis plus confidence-gated tempo tracking; typed bass/kick, snare and high-percussion colours, optional single-colour flashes, and temporary recurring-sound fingerprints.
- Adjustable update rate (1–30 Hz), smoothing, brightness, thresholds, and named presets.
- Launch at login, optional restore on launch, sleep/wake handling and reconnect attempts.
- Serialized USB request/reply exchanges, response validation, bounded recovery, and a process lock against competing MiniChroma instances.
- Hardware diagnostics and command-line tools.

Audio defaults to **25 Hz** in version 0.1.3; other live effects retain the 10 Hz default. A five-minute test on the listed mouse delivered **7,500 validated frames at a 25 Hz target with zero errors**. This is evidence for that device and setup, not a guarantee for every hub or firmware. See [verification](VERIFICATION.md).

## Build and run

For the prebuilt app, [download MiniChroma.zip](https://github.com/KMThegamer2022/MiniChroma/raw/refs/heads/main/MiniChroma.zip), extract it, and move MiniChroma.app to Applications. This build is signed for local use and is not notarized.

Requires Xcode with the macOS SDK. There are no third-party runtime dependencies.

```sh
zsh build.sh
open dist/MiniChroma.app
```

The script builds the `MiniChromaApp` Xcode scheme in a temporary directory, signs for local use, verifies the signature, and creates `dist/MiniChroma.app` and `dist/MiniChroma.zip`. Set `MINICHROMA_OUTPUT_DIR` to an absolute directory to choose another output location. By default signing is ad hoc. Set `MINICHROMA_SIGNING_IDENTITY` to your existing development signing identity to keep a consistent certificate-based identity across rebuilds. Builds are not Developer ID notarized. Replacing signing identities can require macOS to ask for permission again.

Alternatively, open `MiniChroma.xcodeproj`, select **MiniChromaApp**, and Run. This scheme builds the `.app`; the separate Swift package executable scheme serves command-line development.

Move the built app to Applications before enabling launch at login. Open it, then click the mouse icon in the menu bar. The app has no Dock icon.

## Using the controller

Choose an effect, adjust its controls, and click **Apply**. **Light off** selects firmware off. **Stop** ends live updates but leaves the last colour displayed.

Volume maps green → yellow → red and uses black when muted. Battery maps green at full charge toward red at empty. Adjust the yellow threshold in Settings. Some audio outputs do not expose software volume; battery requires an internal Mac battery.

Version 0.1.2 uses a **CoreAudio process tap for system audio only**. It does not enumerate displays, capture screen pixels, or use ScreenCaptureKit or microphone input. macOS may ask for permission to record system audio. No recording is saved or transmitted. Adjust gain, noise gate, and smoothing for the audio source.

Audio uses green for quiet sound, yellow in the middle, and red at the loud threshold. Gain sets that threshold for the captured digital RMS signal; it is not an acoustic decibel measurement. Audio below the noise gate and missing samples turn the light fully off, including when smoothing is enabled. A healthy silent tap is left running instead of being recreated and requesting permission again. An unavailable tap/device restarts with a bounded retry/backoff policy; wake waits for prior cleanup. Denied permission waits for explicit Apply.

Version 0.1.3 smooths the scalar audio envelope before mapping its colour and interpolates on every 40 ms RGB frame, even between audio callbacks. A short dropout fades rather than flickering directly off; sustained silence reaches exact black after a bounded release (about 200 ms including sample freshness at 25 Hz). The Smoothing control adjusts response, with a short anti-flicker envelope retained at its fastest setting. The previously selected audio preset is upgraded to 25 Hz once, preserving its other settings; other preset rates are unchanged.

Colour controls now open a dedicated editor with a visible swatch, RGB sliders, hex readout and basic colour buttons. This replaces the picker embedded in the menu popup. Click Apply effect after editing a firmware or custom pulse colour.

### Beat Adapt

Choose **Beat Adapt**, edit the **Bass / kick**, **Snare** and **High percussion** swatches, and click **Apply**. Defaults are red, blue and yellow. Turn **Separate percussion colours** off to use your preserved single **Flash colour** instead. It uses the same audio-only CoreAudio tap and 25 Hz RGB link, but analyzes actual PCM at audio-callback rate rather than trying to infer beats from 25 Hz loudness values. Bass/high transient features drive onset flashes; repeated, corroborating hits establish tempo/phase. BPM and tracking confidence appear only when the estimate is locked.

**Beat sensitivity** changes transient sensitivity. **Steady ↔ detailed** controls the strength of extra high-percussion flashes. Kick and snare attacks give strong flashes, including syncopated/offbeat hits. Tempo is an informational guide and never generates an unplayed metronome beat. **Pulse decay** sets the smooth fade. Start near sensitivity 1, detail 0.5, decay 0.18 seconds. One mouse LED zone displays one event colour at a time. Near-simultaneous events prefer bass/kick, then snare, then high percussion; later events take over and fade without colour blending. This remains separate from Audio reactive's green/yellow/red loudness map.

**Percussion focus** conservatively requires transient shape and spectral evidence, reducing harmonic/vocal-like and slow sibilant triggers; it may also miss softer drums. **Learn recurring percussion** keeps temporary amplitude-normalized spectral fingerprints. Only convincing attacks train them; three recurring hits establish a sound family. Once established, unfamiliar sounds undergo probation, so changed drums may need a few hits to appear. Quiet matching hits do not retrain the model. Silence (including an audio-callback gap), capture restart and wake reset the fingerprints. Nothing is saved as audio or persisted as a learned song model. Learned-sound count is shown only for actual promoted fingerprints.

Version0.4 adds adaptive analysis-level normalization for quiet passages, a background-subtracted32ms tail spectrum, and one joint event group that gathers about35ms of attack/decay evidence. Bass-first classification is removed; sustained low backing cannot block a valid snare decision. Learned fingerprints compare across types for ambiguous decisions, with more tolerant same-class matching only for independently convincing attacks. Near-simultaneous kick/snare events produce one stable priority colour rather than competing updates.

Analysis uses a 64ms Hann magnitude spectrum with a 5ms hop and adaptive band novelty to reduce sustained-note false triggers. Best results still come from clear percussion. Dense mixes, vocals and missing kicks can produce missed/extra hits or uncertain, half/double-time or incorrect estimates; confidence measures rhythmic agreement, not a calibrated probability of correctness. It does not separate instrument stems or guarantee every song. Steady-tone and silence tests reject a claimed tempo, and old history resets after a long quiet gap. No beat is scheduled indefinitely in silence.

CPU temperature displays the hottest validated M4 CPU-core sensor and its key. The read-only AppleSMC interface is private and experimental; an OS update may change it. It samples once a second, never controls fans or writes SMC settings, and reports unavailable if its sensor requirements are not met. Cool/hot thresholds are adjustable in Settings.

Presets are saved in `~/Library/Application Support/MiniChroma/presets.json`. Settings also controls launch at login and restore on app launch. Automatic restore defaults off.

## Diagnostics and tests

Quit MiniChroma and any other RGB controller before running command-line hardware diagnostics:

```sh
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer swift test
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer swift run minichroma-diagnostic read
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer swift run minichroma-diagnostic temperature
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer swift run minichroma-diagnostic stream 25 300
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer swift run minichroma-diagnostic off
```

`read` checks firmware without changing the logo. `stream` animates the logo for the requested duration, validates every reply, and finishes with off. `off` additionally sets brightness to zero and reads it back. Hardware tests require the listed mouse to be connected.

The app's Diagnostics window offers metadata reads and shorter effect/rate tests. The app executable also accepts `--system-test` (real volume/battery/CPU/rainbow/pulse pipeline) and `--audio-test` (real audio capture with a short local Apple sound). These change lighting temporarily and finish with off/zero brightness.

`--beat-test` generates a short local syncopated 120→150 BPM full-mix fixture (drums, sustained synth/bass and vocal-like modulation), taps only its playback process to avoid unrelated background audio, and checks distinct onset/pulse timing and USB replies. It does not play or verify an actual commercial recording. The normal mode still captures system audio. This diagnostic restores the prior selected preset and finishes with off/zero brightness. `--percussion-live-test` instead observes currently playing system audio for 20 seconds with typed colours and validated USB replies, changes no playback, saves no audio, restores the selected preset and finishes off/zero brightness.

`--beat-observe` uses the global audio-only tap for 25 seconds and prints timing and band/novelty statistics. It writes no audio samples and sends no USB commands. Review timing logs before sharing.

Visual effect behavior, pointer usability, physical reconnect, sleep/wake, and login launch need observation on the actual setup. Automated tests and USB acknowledgements cannot prove those physical interactions.
